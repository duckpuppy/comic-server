# Library Tools

Workflow-page and book-page tools that inspect or fix library records.

Moved from `CLAUDE.md`. See the index there for the other developer reference files.

## Needs Attention Flags

`internal/attention` (comic-server-z77p) derives named, severity-ranked flags from each book record alone: `is_pdf`, `is_zip`, `needs_conversion`, `cover_only`, `no_series`, `low_page_count`, `unknown_publisher`, `missing_format`, `missing_count`. Computed in the same pass as the workflow stage cache (`workflowCacheEntry.booksByFlag`), so it shares `InvalidateWorkflowCache`. `GET /api/library/attention` returns flags ranked severity > count; `GET /api/library/attention/:flag/books` pages the matching books. Shown as a "Needs attention" panel on the workflow page. Idea from ComicManager (ideas only, AGPL). A flag can be **accepted** (hidden) on one book (comic-server-x7rd): `attention.KeyAccepted` = `comic_server_accepted_flags` custom value (`+`-joined), skipped in the workflow-cache pass, set via `POST /api/library/books/:id/accept-flag {flag, accepted}` (audited as `accept_flag`); Accept buttons on flag drill-ins and the book page, which also lists accepted flags with an undo. `file_missing` (comic-server-4q1z) comes from a background pass (`internal/api/diskcheck.go`): stats every book's resolved path (off the request path, metadata only, 10ms pause per 500 books, every `disk_check_interval_hours` = 24 by default, `-1` disables; env `COMIC_SERVER_DISK_CHECK_INTERVAL_HOURS`; chosen slow because the library sits on shared disks that also stream media), merges the last finished result into the flag cache, and invalidates the cache when a pass ends. It is off unless `SetDiskCheckInterval` is called (cmd/server.go does from config; not re-read on SIGHUP); results are empty until the first pass finishes. A wrong path mapping flags every book, so check mapping first if the count is huge. Cross-checks (comic-server-8fee, `internal/attention/crosscheck.go`): `count_mismatch` (Count > 0 differs from a synced volume's CV issue count), `metadata_mismatch` (the tagged `comicvine_issue` is cached with a different number, or under a different volume than `comicvine_volume`), `cv_volume_conflict` (siblings with the same compressed series + Volume > 0 + Format tagged with different CV volumes; the minority is flagged, both sides on a tie), `format_mismatch_in_volume` (comic-server-0vu9: books of one `comicvine_volume` whose non-empty Format differs from the volume's majority; same `minorities` helper). CV data is a memoised snapshot (`Server.cvAttentionData`, 10 min TTL): synced counts plus `Cache.IssueRefs` for only the library's issue IDs, chunked 500 per query. Unknown (unsynced/uncached) is never flagged. `corrupted_archive` (comic-server-4inw) is recorded **lazily**, never by a scan: every archive open that fails goes through `comicvine.openFailure`, which calls `comicvine.SetArchiveFailureHook` (wired in cmd/server.go to `Server.RecordArchiveFailure`) when the failure looks like corruption (`IsCorruptOpenError`: the container did not parse; missing file, permission, I/O or mount errors and password-protected RARs are not corruption). Failures live in the config.db `archive_health` table (lazy, keyed by resolved path with the file's mtime-size), are patched into the cached flag lists in place, and clear themselves when the file's version changes; Accept works as for any flag. The list therefore only knows files that something read (cover requests, page views, convert, scrape cover checks) and grows as the library is browsed. **Optional archive scan** (comic-server-yn10, `internal/api/archivescan.go`): `archive_scan_interval_hours` / env `COMIC_SERVER_ARCHIVE_SCAN_INTERVAL_HOURS`, **0 = off (default)**. A background pass opens each CBZ/ZIP/CBR/RAR/CB7/7z index via `comicvine.ListPageNames` (no page data; failures reach the same hook), 20 opens then a 250 ms pause. A file that opens cleanly is stored with its mtime-size in config.db `archive_verified` (lazy table), so a restart resumes and later passes read only new or changed files; non-corruption errors (I/O, permission) are retried next pass. Not re-read on SIGHUP. Not done: scrape results (`scrape_no_match` is covered by the Scrape Review card; `scrape_error` not done).

## Relink and Remove (missing files)

**Letter case** (comic-server-bj3j): a library written on Windows ignores case, a Linux disk does not (prod 2026-10-15: 500 books whose folder was `Journey Into Mystery` on disk, `Journey into Mystery` in the XML). `pathmap.ExistingCase` (called last in `Config.ResolveLibraryFilePath`, so every file read, the disk check and sync use it) returns the on-disk spelling when the exact path is missing and each component has exactly one case-insensitive match; two spellings are never guessed. Directory listings are cached 5 minutes. An existing path costs one extra stat. The stored `FilePath` is not rewritten.

comic-server-heox. A book flagged `file_missing` (disk pass, see Needs Attention Flags) gets two fixes. **Relink** (`internal/relink`, `POST /api/library/books/:id/relink {apply}` and bulk `POST /api/library/workflow/relink-missing {apply, book_ids?}`) looks only in the book's own old folder - one directory listing per folder, never a library walk (shared disks). Strategies in order, each needing exactly one candidate: same file name ignoring case and extension (an archive converted or renamed in place), then a name that parses to the same compressed series + issue number (`comicvine.ParseFilename`). Two fits is `ambiguous` and is reported, never guessed; a file another book already uses never matches; the old folder gone is `folder_missing`. `apply` false is a preview that changes nothing; apply sets only `FilePath` (kept in the library's own path style, so a Windows raw path stays Windows-style) and `FileSize`, audited as `relink`, and drops the book from the in-memory disk-check result so the flag clears at once. **Remove record** (`POST .../books/:id/remove-record`) deletes only the library record, never a file, and refuses (409) when the file is back or the book has no file; audited as `remove_record`. UI: "Relink missing files…" (preview, confirm, apply) on the file_missing list; "Relink file…" / "Remove record…" on a missing book's page. **Manual pick** (comic-server-679r): `POST .../books/:id/relink` also takes `file_path` (a path on the server's disk, from the `browseServerFile` picker); the book page offers it when the old-folder search finds nothing. The pick must be a regular comic archive, not used by another book, and (when `library_root` + `library_source_root` are set) under `library_root`; it is stored under `library_source_root` in the old path's separator style. Statuses `pick_invalid` / `pick_taken`; same preview/apply and audit as the folder search. The picker opens in the book's old folder, or its nearest parent that still exists (`RelinkOutcome.start_dir`, `nearestExistingDir`); `/` when none is left. **File already used** (#3): `RelinkOutcome.taken_by` {book_id, series, number, title, path} names the other record when a pick is `pick_taken`, and also on `not_found` when the old-folder search had a fitting file another book owns (status unchanged, so existing clients still work; bulk relink is unchanged). The book page shows a dialog with a link to that record and "Remove this record…" for the missing one; merge (copying reading progress) is not built. Not done: the expected-folder search ComicManager has (needs the organizer profile).

## Duplicate Review (internal/duplicates/)

comic-server-as8l. `/duplicates` page + `GET /api/library/duplicates` (`?covers=1` adds the slower within-series cover-dHash signal) and `POST /api/library/duplicates/resolve` (`keep` | `keep_trash` | `keep_all`). Detection (`duplicates.Detect`, pure) groups by ComicVine issue ID, series+number+volume+format (reuses `library.CompressedSeriesName`), cover dHash (anchor-based, Hamming <= 5), and copy-style filenames; groups spanning > 3x page count are dropped, and a fileless book (physical-copy entry or Wanted placeholder) never groups with a file-backed one (`kind` prefix on the CV and series-number bucket keys). A "Re-scrape the kept book" checkbox makes the page POST `/api/scrape {book_ids:[keeper]}` after Keep / Keep and trash (full search, not fast rescrape, since the old tag may be the wrong one; 409/503 shown as a toast, the keep still stands). `keep_trash` quarantines losers via `internal/trash` (never `os.Remove`) and refuses to trash a file shared with the keeper. Decisions live in config.db (`duplicate_keep_all` keyed by hash of member IDs, `duplicate_resolved_books`; tables created lazily, no schema bump). `keep_trash` also removes each loser's library record via `library.Backend.DeleteBook` (XML: dropped from the library; SQLite: soft-deleted with `deleted_at`, like an import retiring a vanished book; logged to the audit log). `duplicate_resolved_books` remains as the safety net against a re-import resurrecting the record. The book is not removed from reading lists' explicit member lists; unresolvable members are ignored on read.

## Format Detection

comic-server-izc7. `internal/formatdetect` proposes a `Format` from the book record: ordered rules, first match wins, order taken from ComicManager's formatting guide (ideas only): Director's Cut and Black & White (series/title), Omnibus and TPB (series/title/summary), 80+ pages with "Collects"/"#1-5" in the summary is TPB, 500+ pages is Omnibus, Annual, Preview(s), then by `Count`: none = no match (so `missing_format` stays), over 15 = Series, **issue number over 15 = Series even with a small count (continuation / renumbered series)**, 2-15 Limited Series, 1 One-Shot. Chosen over Data Manager rules because it needs state DM rules cannot hold (our own last write, the count it was based on) and ships defaults (DM rulesets are user data). Hardcover/Absolute/Graphic Novel are manual-only.

- **Never overwrites a manual choice**: only an empty `Format`, or one still equal to `comic_server_format_auto` (what detection last wrote), is touched. `comic_server_format_locked=1` skips a book outright. A count change re-detects books whose Format is still ours.
- **API**: `GET /api/library/workflow/format-detect` previews (total, per-format counts, first 100 rows) and writes nothing; `POST` applies, audited as `format_detect`. Wanted placeholders (no FilePath) are skipped; paper copies are not.
- Known risk: a regular issue whose summary mentions "omnibus"/"TPB" (e.g. "collected in the TPB") is classified by that keyword, as in ComicManager. Check the preview before applying.
- UI: "Detect Format" card on the workflow page (comic-server-6y63). Not done: feeding Format into organizer folder structure.

## Count Fill

comic-server-08jr. `internal/countfill` fills `Count` from the ComicVine cache (`cv_volumes.issue_count` via `Cache.SyncedIssueCounts`), so format detection has a count to work with. Only a `Count` of 0, or one still equal to `comic_server_count_auto` (what this last wrote), is touched; that lets a re-run follow a growing ongoing series without overwriting hand-set counts. Untagged books and volumes not yet synced are skipped (unknown is not zero; the preview reports them as `waiting`). Wanted placeholders are included (Count is metadata, no file I/O).

- **API**: `GET /api/library/workflow/count-fill` previews (total, volumes, waiting, first 100 rows); `POST` applies, audited as `count_fill`. 503 without a ComicVine cache.
- **Files**: filled counts are normal metadata and go into ComicInfo.xml on the next comic-server write. Only books comic-server already wrote (they have `comic_server_written_hash`) show as stale afterwards; nothing sets ComicRack's dirty flags. Decided 2026-10-13 over keeping CV counts out of files.
- Run count fill before format detection. UI: "Fill Issue Counts" and "Detect Format" cards on the workflow page (comic-server-6y63); preview loads only on click (each GET scans the library), Apply behind a confirm.

## Book Edit Form

`POST /api/library/books/:id/edit {fields, read}` (`internal/api/bookedit.go`), the "Edit" button and form on the book page, and "Mark as read/unread" there. Only fields sent are written (the form sends just what changed), through `datamanager.SetFieldString`; the allowed set is `editableFields` (FilePath and other file fields are not editable). Ratings 0-5, Month/Day/Year ranges and Yes/No/Manga values are checked; "Unknown" is stored empty. `read` follows ComicRackCE `MarkAsRead`/`MarkAsNotRead`. Changing a ComicInfo field on a book with a file sets `ComicInfoIsDirty` (so it shows under Out-of-date Files); any change sets `ComicBookIsDirty`; a field the organizer could use sends a filed book back to `StageToMove` (not Rating, Summary, Notes, Review or collection fields). Audited as `edit`. Not done: custom values, multi-book edit.

## Workflow Hero

comic-server-p7ti. Top of the workflow page: percent clean (Organized / every staged book; hidden when no book is staged), a 14-day sparkline of stage advances with this-week vs last-week delta, and a cover strip of the most recently advanced books. No new table: `GET /api/library/workflow/throughput` folds `audit_log` rows whose stage moved forward (`configdb.ListStageMoves`, `buildThroughput` in `internal/api/throughput.go`). A book moving two stages counts twice; rollbacks count nothing. History is only as old as the audit log (180 days, and it only exists from vqsj onward), so a fresh install shows zeros. Reverse sync and CLI scrape/backfill are not audited, so they do not appear.

## Paper Copies

comic-server-vffq. A paper copy is a book with no `FilePath` and ComicRack's own `BookCollectionStatus` = "Physical" (any case; `library.IsPhysical`). Every other fileless book is a Wanted placeholder (`library.IsWantedPlaceholder`) - the user's existing fileless books (1,529 on prod, 2026-10-14) are Wanted, so the marker must be explicit. ComicRack's field was chosen over a `comic_server_` value so ComicRack shows it, smart lists match it and export keeps it. Paper copies count as **owned** in completeness / Missing Issues (decided 2026-10-14), are left out of the Wanted list, cannot be linked to a file via the Wanted link flow (409), and get format detection (metadata only); they never enter the workflow (no file). `BookLocation`/`BookCondition`/`BookNotes` hold storage, grade and notes.

- **API**: `POST /api/library/physical` adds one (409 if a paper copy with the same compressed series + Volume + number exists); `POST /api/library/physical/import {csv, apply}` previews or applies a CSV: header row matched case-insensitively ignoring spaces/_/-/./# with aliases (Issue, Vol, Storage/Box, Grade, CV Issue...), Series required, 10,000-row cap, rows already present (library or earlier in the file) are `exists` and skipped so re-imports add nothing. Audited as `physical_add`.
- **UI**: `/physical` (Library > Paper Copies): add form that keeps series/volume/publisher/location for the next issue, CSV paste or file with preview then Import. Browse rows and the book page show a Physical / Wanted badge (`ComicPreview.kind`, `BookDetail.kind`). The router now URL-decodes route params, so ids like `{guid}` (every comic-server-created book) open on the book page.
- Duplicates still put all fileless books in one bucket kind, so a paper copy and a Wanted entry for the same issue are shown as a group.

## Browse Quick Search and Sort

`POST /api/library/browse` (and the Browse-scoped Data Manager endpoints) accept an optional `query`, `sort` and `sort_desc` (comic-server-mzkf). `query` narrows the matched set and never widens it: with no matchers and no `show_all` the result is still empty. Plain words must each appear in series/title/publisher; `#N` matches issue number (leading zeros ignored), `(YYYY)` year, `VN` volume (`library.ParseSearchQuery`, `internal/library/searchtokens.go`). `sort` is one of series, number (numeric-aware), title, publisher, year, volume, pages; books with an unset value (no page count, no year...) sort last in both directions. The query is passed to the Data Manager preview/apply scope so a bulk action acts on exactly what the preview shows; it is not saved with "Save as Smart List".

**Filter rail and views** (comic-server-j6lk): `facets {publishers, formats, stages, flags}` on the browse and Browse-DM requests narrow after the query (OR within a facet, AND across; `""` = no value; publisher/format case-insensitive; flags from the workflow cache, so accepted flags are excluded). The first page (offset 0) returns `facets` counts over the matchers+query set before any facet, so ticking one option keeps the others visible (`internal/api/browse_facets.go`). The page keeps matchers, show_all, query, sort and facets in the URL (`history.replaceState`), so Back from a book page and bookmarks restore it; the Table/Grid/Compact view is a per-browser localStorage preference. Facets are not saved by "Save as Smart List".

## Manual Lists

Tracker #9 (was comic-server-k1bt.4). ComicRack's plain "List" (`ComicIdListItem`, ordered `BookIds`), filled by hand; until this, comic-server could only browse such lists (ones made in ComicRack) and make reading lists by CBL import. `internal/api/manuallists.go`: create/rename/delete use the normal list endpoints (`type: "ComicIdListItem"`); `POST /api/library/lists/:id/books {book_ids | browse, index?}` adds (already-present books are skipped, not moved; `browse` reuses the bulk-edit scope, cap 10,000), `.../books/remove {book_ids}`, `.../books/move {book_id, index}` (final 0-based position, clamped); `GET /api/library/manual-lists?book_id=` feeds the picker. Every write first rebuilds `BookIds` from `GetBooksForList` (drops ids that no longer resolve and repeats, as ComicRack's `OnGetBooks` does), so an index means the same row the list preview shows. Writes are serialized by `Server.manualListMu` (read-modify-write of the whole list). Only `IdListItem` types are editable: smart lists and CBL `ComicReadingList`s get 409 (a CBL reimport replaces membership). Adds/removes are audited per book as `reading_list` (`{field: "list"}`); rename, reorder and delete are only logged, like smart list edits. UI: "+ New Manual List" on the lists page, "Add to list…" in the Browse bulk bar and on the book page (`js/manualLists.js`, `ManualLists.pickAndAdd`), a Lists section on the book page, and ⤒ ↑ ↓ # ✕ controls on the list page's preview cards. Found while building it: SQLite `UpdateListRecord` used to move every edited list to the root (it now keeps `parent_id`) and XML `DeleteList` reported a list inside a folder as not found. Each XML-backend write saves the whole ComicDb.xml, so reordering a big XML library is slow per click. A later XML re-import into SQLite soft-deletes lists the XML does not have, these included (same as smart lists made in comic-server). Not done: drag-and-drop reordering, adding at a chosen position from Browse.

## Browse Bulk Edit

comic-server-k1bt.2. ComicRack's multi-book Info dialog for Browse. Rows have checkboxes (table, grid, compact); ticking every loaded row offers "Select all N matching", which makes the Browse filter (matchers/show_all, query, facets) the scope instead of ids. `js/browseBulk.js` (`BrowseBulk`) draws the bar and editor; a fresh search clears the selection. `POST /api/library/browse/bulk-edit {book_ids | browse, expected_count, edit, apply}` runs the single-book edit (`BookEditRequest`, same field checks, dirty flags, stage regression and `edit` audit rows) over the scope. `apply` false previews (counts per field, first 20 books) and writes nothing; apply needs `expected_count` equal to the scope's size now (409 otherwise, so the library cannot shift under a preview). Every book is computed before any write, so a rejected value writes nothing. Cap 10,000 books (413, narrow the filter), written 500 at a time. List fields (Genre, credits, Characters, Teams, Locations, Tags) take `list_add` / `list_remove` (case-insensitive, existing spelling kept) besides replace; the single-book endpoint accepts them too. Number is not offered in the bulk form. Mark read/unread uses `edit.read`. No undo: the old values are in the History page. Browser-smoke-tested on a scratch library (note the XML backend flushes to disk about 30 s later).

**Find and replace** (tracker #31). `edit.find_replace {field, find, replace, ignore_case, whole_word}` on the same endpoint (`FindReplace` in `internal/api/bookedit.go`, so the single-book edit takes it too). Plain text, no regex; the replacement is literal (`$1` stays `$1`). Whole word means the characters next to a match are not letters, digits or `_` (checked by hand, RE2 has no lookaround). Allowed on text fields only: `findReplaceField` refuses numbers, dates, yes/no/enum fields, Format, AgeRating, LanguageISO, BookCollectionStatus; `comic_server_` custom values are not in `editableFields`, so they can never be replaced. A field cannot also be set, added or removed in the same edit; empty `find` is a 400. A list field is changed as its whole comma-separated text (no per-item dedupe; use `list_add`/`list_remove` for items). A book that does not contain the text is unchanged ("unknown is not zero": nothing is written for it). The preview samples carry `diffs` [{field, before, after}] (first 20 books, any bulk edit, not just find and replace); the UI shows them as before -> after. UI: "Find & replace…" in the Browse bulk bar (`BrowseBulk.renderReplace`), same preview then confirm then apply, same `expected_count` guard, dirty flags and `edit` audit rows. Data Manager rules were checked first: their `Replace` action is case-sensitive, has no whole-word option, lives in saved rulesets and has no per-book before/after, so this is a real feature, not an entry point to a rule. Not done: regex, replacing across several fields at once. Browser-smoke-tested on a scratch copy of the test library.

## Browse Stacks

Tracker #11. `group_by` (series | publisher | year | format) on the Browse request (`internal/api/browse_group.go`) returns `stacks` (key, label, sub, count, unread, cover_id; paged by stack, `total` = stacks, `total_books`) instead of books; sort `count` orders stacks by size, unset values ("(no series)") go last. A series stack is compressed series name + Volume (so "The X-Men" and "X-Men" vol 1 are one stack, vol 2 another); its cover is the lowest numbered issue. Opening a stack sends `group_key` with the same filter: the response is that stack's books, in issue order unless a sort is set. `resolveBrowseCandidates` honours an open stack, so bulk edit and Data Manager scopes act on just that stack; they never get the stack list. UI: "Stack by" select, `group`/`gk`/`gl` in the URL, "← All stacks" button. No index: grouping 67,000 books takes about 10 ms and opening a stack about 5 ms in memory (benchmarks in `browse_group_test.go`); the one cost was `CompressedSeriesName`, now memoised (`compressedSeries`). Browse runs over the in-memory book list, not SQL, so a database index would not be on this path. Browser-smoke-tested on the 10-book test library only.

## Browse CSV Export

Tracker #13 (ComicManager's CSV list export). "Export CSV…" on Browse opens a column picker and downloads every book the current filter matches (matchers or show all, quick search, facets, an open stack; the whole set, not the loaded page), in the order shown. `POST /api/library/browse/export-csv {browse: BrowseRequest, columns?}` (`internal/api/browseexport.go`); `GET /api/library/browse/export-columns` lists the 43 catalog columns (library fields by name, plus Read, File name, File path, ComicVine volume/issue id, workflow stage, Kind) and which are default; `custom:<key>` also works as a column. UTF-8 with a byte order mark (Excel), a zero number is an empty cell, and a cell that starts with `=`, `+`, `@` or a non-numeric `-` gets a leading apostrophe (spreadsheet formula injection; `-1` stays). 409 when no book matches. The chosen columns are remembered per browser (localStorage). Not done: exporting a saved smart list or reading list directly from its page (use Browse with the list's matchers), a Windows-style CRLF option, column order other than the catalog's. Autonumber and search-and-replace from the same ComicManager gap are separate issues (#13 was split).

## Collected Editions

Epic #36, data model #38. A collected book (TPB, hardcover, omnibus, event book) keeps **its own identity** (series, number, ComicVine tag, Format) and carries a separate list of the issues it contains. The list is local to comic-server: ComicVine cannot be edited and ComicRack ignores `comic_server_` values.

- **Storage**: `internal/collects`, custom value `comic_server_collects`. One entry = one run of issues of one series: `volume` (ComicVine id, 0 if unknown), `series` (name hint), `from` / `to` (issue numbers as text; `to` empty for one issue), `kind` (`main` | `backup`), `partial`, `source` (`manual` | `suggested`). An event book holds several entries. Custom values split on `,` and `=`, so `collects.Encode` percent-escapes every field (letters, digits and `._-` stay) and joins entries with `+`, fields with `|`. `Decode` skips a damaged entry instead of failing. A book with no links is "not linked yet", not "collects nothing".
- **Never mixed with single issues**: `duplicates.kind` puts a book with links in its own bucket, so a TPB never groups with the single issues it contains (two copies of the same TPB still group). Later children (#41) keep it out of owned counts the same way.
- **API**: `POST /api/library/books/:id/collects {entries}` replaces the list, `[]` clears it. Validated (`collects.ValidateAll`: a volume or series name, a first number, known kind/source, at most 200 entries), audited as `collects`, so History, undo and field locks work through the normal `custom:comic_server_collects` diff. `GET /api/library/books/:id` returns `collects`.
- **UI** (#39): `web/js/collectsEditor.js` (`CollectsEditor`), the "Collects" section on the book page (open when links exist or the book is marked `collected`) and a collapsed "This is a collected edition" box on each Scrape Review item. One row per run of issues; "Add another series" adds a row (events); each row has a ComicVine volume link/id (Look up fills the name), from/to, story or backup story, partial. Preview, then Confirm: nothing is saved before. Clear all removes every link.
- **Lookup and warnings**: `POST /api/library/books/:id/collects/lookup {ref}` is read-only; it takes a volume link/id (an issue ref is refused) and returns the volume plus its issue numbers (cached volume = no API call, else one paced call, same 429/503 handling as `cv-match`). `POST .../collects` with `preview: true` validates and returns `warnings` (one list per entry) without saving; a normal save returns them too. `collects.Warnings` flags a first/last number that is not in the volume's cached issue list and a backwards range. Warnings never block, and a volume that is not cached gives none (unknown is not a warning). Volume search by name is not built: paste a link or id.
- **Covered state** (#41): Missing Issues and the series-completeness API show an issue with no book of its own, inside a collected edition the library holds, as `covered` (`covered_by` = the collected book), separate from `owned`. `comicvine/missing.go`: `addCollectionRuns` / `coveredByEntry`. Only whole-issue runs with a ComicVine volume count (a backup story, a partial issue, a name-only entry or a Wanted placeholder covers nothing); a range with a missing end or running backwards covers nothing; owned wins over covered. `missing` = neither owned nor covered; `percent` stays owned-only. A volume known only through a collection appears in the list once its issue list is synced, and `SeedFromLibrary` / `BuildOwnedCounts` include collection volumes so they get synced. **Setting** (#46): `count_covered_as_owned` in config.db `server_misc_settings` (schema v14, default off; Settings > Server toggle "Count collected-edition issues as owned"; `GET/PUT /api/settings/server-misc`). Off: collections are `covered` and counted nowhere else, and `BuildCompletenessMap` (the CV smart-list matchers) ignores them. On: `Owned`/`Percent` in Missing Issues include covered issues (`covered_as_owned` is in the response; the covered flag stays on each issue) and the matcher map counts them as owned for the volume's books. Builders: `Build*Opts` with `comicvine.CompletenessOptions`; `Server.completenessOptions()`. Changing the setting drops the Missing Issues memo and runs `Server.RebuildCVData()` in the background so the matchers update without a restart; startup passes the same option through `startComicVineSync`.
- **Local identity** (#43): `internal/localid`, custom value `comic_server_local_id` = `<volume key>|<issue key>` (generated, `lv-` / `li-` plus 10 hex). For a collected book ComicVine never lists. It is **never** written to `comicvine_volume` / `comicvine_issue` (seeding, completeness and the CV matchers expect real ids). The book keeps its own Series and Number (edit them with Edit; a book with no series name is refused). Sibling books of one line share the volume key and each has its own issue key. `POST /api/library/books/:id/local-identity {set, preview, sibling_ids}`: `preview` lists books with the same series name (case and spacing ignored), a file and no ComicVine volume, saves nothing; confirm saves the book and the ticked siblings, joining an existing volume key when a sibling already has one (audited as `local_identity`, undoable). `set:false` removes it from this book only. `workflow.ExemptFromScrape` is true with an identity, so the book is past the Scrape stage, whole-library scrapes hold it back ("has a local identity") and Scrape Review drops it; setting one removes a not-in-ComicVine marker (the identity replaces that decision); a successful `WriteMetadata` (real match) retires it. Book page: "Give a local identity…" next to "Mark as not in ComicVine", a "Local identity" badge, "Remove local identity". **Re-link** (#44): a single book is matched with the normal "Match by ComicVine link or ID" box; `WriteMetadata` writes the real tags, retires the identity and leaves `comic_server_collects` alone. For a whole line, the book page shows "Link this whole line to a ComicVine volume" (`web/js/localLine.js`, `LocalLinePanel`): `POST .../local-identity {line:true}` lists the books sharing the volume key (with a file); paste the ComicVine volume, each book is matched to the volume issue with the same number (a book with no matching number is left unticked), then the page calls `cv-match {issue_id, apply:true}` once per book, this book last. Each apply is one paced ComicVine call (issue detail, cached after), so a 429 stops the run with a message and Continue picks up the rest; nothing is queued on the server. **Not built**: the optional background re-check of local-identity books (off by default); migrating existing `collected` markers (they stay as they are, the identity is a manual choice per book).
- **Suggested links** (#40): a collected book's description often says "Collects GHOST RIDER (2006) #33-35". `collects.ParseSummary` reads the statement after the first "collects / collecting" (several series, bare follow-on ranges like `, 591-594`, `and #20` continuing the last title, en/em dashes, a year in brackets; it stops at the end of the sentence; "starting with" adds a note; a range with no title is dropped with a note). `comicvine.VolumeIndex` (from `Cache.NamedVolumes`) then looks each title up among the volumes **already cached** by normalised name (case, `&`/and, leading "The" and punctuation ignored): name + year match is `high`, a single name match with no year is `medium`, anything else (none, several, wrong year) is `low` and becomes a series-name-only entry. No ComicVine call is made, so a series the library holds no book of stays `low`. `collects.Warnings` against the cached issue numbers lowers `high` to `medium`. Suggestions are computed on demand (memo 2 min, `Server.collectsSuggestions`) for books with a file, a description containing "collect", no links yet and not dismissed; the only stored state is the mark `comic_server_collects_dismissed`. `GET /api/library/collects-suggestions?q=&min=high|medium&limit=&offset=`; `POST /api/library/collects-suggestions/:bookId {action: accept|dismiss, keep: [entry positions]}` recomputes the proposal from the book (never trusts entries from the page) and saves with `source: suggested` through the normal audited `collects` path. UI: Library > Collects Suggestions (`web/js/collectsSuggestionsPage.js`); confident entries come ticked, low ones unticked. Not built: editing an entry before accepting (accept, then edit on the book page), looking unmatched titles up on ComicVine (would cost paced API calls), parsing Format-less books differently (any description that parses is offered), an Undo for Dismiss.
