# Login and Single Sign-On

Built-in login, API tokens, CSRF, trusted proxies and OIDC single sign-on.

Moved from `CLAUDE.md`. See the index there for the other developer reference files.

## Login (built-in)

Tracker #21 (step 1 of #10; Authelia OIDC is #22, not built). `internal/auth` + `internal/api/auth.go`. **Off until a password is set**, so an upgrade cannot lock anyone out. One admin password (argon2id, min 12 chars), cookie sessions (30 days, HttpOnly, SameSite=Lax, `Secure` only when the request was HTTPS), API tokens (`cs_...`, stored as SHA-256, shown once). All in config.db (lazy tables `auth_credentials`, `auth_sessions`, `auth_tokens`, no schema bump). One gate in `Server.ServeHTTP` (`authGate`): everything under `/api/`, `/ws`, `/metrics` needs a session or `Authorization: Bearer` token, except `openAPIPaths` (`/api/health`, `/api/version`, `/api/auth/status|login|logout`). Web UI files stay open (no data in them); `js/auth.js` wraps `fetch` and raises a login form on any 401. A test (`TestEveryRouteNeedsLoginOnceEnabled`) reads every `mux.Handle*` path from the package source and checks it answers 401 - a new route is covered automatically; add to `openAPIPaths` only on purpose.

- **CSRF**: for a cookie session, a write (not GET/HEAD/OPTIONS) with an `Origin` (or `Sec-Fetch-Site`) that is not same-origin gets 403. No Origin and no Sec-Fetch-Site is allowed (not a browser page). Tokens skip the check. The WebSocket upgrade uses the same check (`upgrader.CheckOrigin`). Same-origin means `Origin` host equals `Host`, or `X-Forwarded-Host` when the peer is a trusted proxy - a proxy that rewrites Host would make every write 403.
- **Trusted proxies** (tracker #24): IPs or CIDRs (`0.0.0.0/0` and `::/0` are refused), default none. Settings > Security saves the list in config.db (`auth_trusted_proxies`, one row; no row = never saved) and it wins over `server.trusted_proxies` / `COMIC_SERVER_TRUSTED_PROXIES` once saved - **a saved empty list means "trust no proxy"** and also wins; DELETE (the "use config.yaml / environment" button) forgets it. It applies at once: the manager re-reads the row at most every 5 s, so `comic-server auth trusted-proxies [addr ...] | --clear` run from a shell works against a running server too. `GET|PUT|DELETE /api/auth/trusted-proxies`; GET also returns `seen` (peer address, whether it is trusted, the client address as read, HTTPS or not, and the raw forwarding headers), which the page turns into "this address sent proxy headers but is not trusted, add it". Only trusted peers get `X-Forwarded-For` (read from the right, skipping trusted hops), `CF-Connecting-IP`, `X-Forwarded-Proto` and `X-Forwarded-Host` believed. Wrong list = the rate limit sees the proxy's IP, the cookie lacks `Secure`, and a proxy that rewrites `Host` makes every write 403 (the way back is the CLI `--clear`).
- **Rate limit**: 10 login or password-check attempts per client IP per 15 minutes (`internal/ratelimit`), 429 after.
- **Lockout recovery** (works with the server stopped, like `restore`): `comic-server auth set-password [--password-stdin]`, `auth disable`, `auth status`. A running server notices within ~5 s. Setting a password signs out every session.
- **API**: `GET /api/auth/status`, `POST /api/auth/login|logout|password`, `GET|POST /api/auth/tokens`, `DELETE /api/auth/tokens/:id`. UI: Settings > Security (`js/securitySettings.js`), and a header "Sign out" button (`#auth-signout-btn`, tracker #25) that `auth.js` shows only when `/api/auth/status` says login is on and this browser is signed in. Logout deletes the server session for password and single sign-on alike (both use the same session cookie); it does not end the provider's own session, so "Sign in with single sign-on" may go straight back in. Logins, failures and token changes go to the log (not the per-book audit log).
**Single sign-on (tracker #22)**: `internal/auth/oidc.go`, `internal/api/auth_oidc.go`, `internal/configdb/auth_oidc.go` (table `auth_oidc`, one row). Authorization-code flow with PKCE (S256) via `coreos/go-oidc` + `x/oauth2`; the ID token's signature, issuer, audience, expiry and nonce are checked. Routes `GET /auth/oidc/start` and `/auth/oidc/callback` sit outside `/api/`, so the gate leaves them open; failures redirect to `/?login_error=<code>` (no provider detail in the address). A sign-in attempt is held in memory (state, nonce, verifier; 10 min, one use, max 500) and tied to the browser by a `comic_server_oidc` cookie (path `/auth/oidc`). Settings (Settings > Security, `GET|PUT /api/auth/oidc`): issuer, client id, secret (never returned; empty on save keeps it; also lands in backups of config.db), **public URL** (explicit, not taken from the Host header; the redirect URI is `<public URL>/auth/oidc/callback`), allowed groups and users. **Deny by default**: saving with SSO on and both lists empty is refused. Users match by `preferred_username`, or by email only when `email_verified`; groups match ignoring case. Groups are read from the ID token and also from userinfo (Authelia returns them there unless a claims policy adds them to the token). SSO needs a local password set first (refused otherwise) and is not offered when local login is off; the password stays as the fallback. `internal/auth/authtest` is a fake provider for tests. **Not tested against a real Authelia** - only the fake provider and the browser form; check the first real sign-in. Discovery is cached an hour and re-run on save; the provider answer is not trusted over `http` except for localhost.
- The first password can be set by anyone who can reach an unprotected server (that is the state before this feature); set it right after upgrading. Devices sync over TCP 7614 and are unaffected. Single user: no per-user attribution.
